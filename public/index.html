Pod Hostname
-
This is the actual container this response came from. Refresh repeatedly — with 3 replicas running, you'll see this value change as Kubernetes load-balances your requests across different pods.
Deployed Version
-
Set by the APP_VERSION env var in the manifest Jenkins commits to git. Bump this by pushing a code change — Jenkins builds it, Argo CD deploys it, and this number updates on its own.
Pod Uptime
-
Seconds since this specific pod started. Drops back to near-zero right after a new deployment rolls out — proof a real restart happened, not a cached page.
Requests Served
-
Counted in-memory by this one pod. Because it's per-pod, not shared, the number you see depends on which replica happened to answer — another small, honest signal of how the load balancing works.
Git push → Jenkins builds & pushes the image → commits the new tag → Argo CD syncs it → Kubernetes rolls it out. No manual kubectl apply, ever.
